## Поведение

- До выбора —0запросов к обоим analytics vendors. Открытие настроек и Escape после несохранённого выбора GA также дают0запросов и не сохраняют согласие.
- Клавиатурные Enter/Space/Escape проверены на390/1440px в обеих темах. Отказ выполняется через«Настройки»→«Без аналитики», сохраняется после reload; настройки повторно открываются с обоими выключенными сервисами.
- Раздельно сохранены Метрика и GA; каждый выбор запрашивает только соответствующий stub SDK. Общее«Разрешить» запрашивает оба. Данные выбора/срок/notice остаются у существующего владельца.
- Отзыв останавливает очереди событий, удаляет доступные сайту аналитические cookie и действует на вторую вкладку. Позднее завершение удержанного SDK-запроса не восстанавливает отозванные queued config/events.
- Сохранены проверки legacy migration, ошибок Storage, session-only состояния, reload и повторного открытия. Несохранённый draft не изменяет действующий выбор.
- Внутри мобильного меню cookie dialog временно подавляет dock; Escape и сохранение возвращают фокус в меню. Проверены390×844 и320×568px.
- Шесть геометрий окна настроек, включая320px и200% текста: подписи действий,44px hit area,12px минимум полей, край scrollbar, отсутствие горизонтального выхода. Общий FAQ-аккордеон проверен mouse/Space/Enter, прерыванием и reduced motion.
- Синтетические analytics events проверяют whitelist параметров и очищенный URL/referrer. Реальная запись, форма или покупка не открываются.

## Изоляция и исправления теста

Harness обслуживает `https://soyuz.hair/` из локального `dist`, чтобы проверить реальную ветвь public-host, отключённую на localhost по договору. Запросы `mc.yandex.ru`/`www.googletagmanager.com` заменяются пустым JavaScript; все остальные внешние providers заблокированы. Настоящие счётчики не выполняются.

Старый harness ожидал удалённую `.analytics-settings-link` и отдельную кнопку отказа в banner. Селекторы обновлены на действующий `data-analytics-settings`, отказ проходит через окно настроек. Добавлен `--label` для отдельных evidence-каталогов и контроль SHA тестируемой сборки.

Два ранних прогона остановились на новой ошибочной QA-проверке ширины, а не на продуктовой ошибке. Минимальная repro подтвердила: viewport/clientWidth390px, но CSS bounds корневого элемента и body386px из-за stable scrollbar gutter. Banner354px корректно равен386−32. Итоговый тест использует фактическую ширину корневого элемента; два прежних каталога сохранены с `HARNESS_FAILURE.json`, не названы PASS.

В этом задании не повторялись Firefox/WebKit, физический Safari/телефон, скринридер или настоящая доставка/обработка данных поставщиками. API очереди и blocked/stub requests не доказывают работу production кабинетов аналитики.
