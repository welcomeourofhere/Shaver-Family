# Проход 57. Совместимость и работа интерфейса

10.11.2026. Локальная программная часть оптимизации завершена. Физические телефоны исключены владельцем из этого этапа. Проверка доступных движков, профилей ввода и размеров выполнена; публикация, реальные записи и аппаратные измерения не выполнялись.

## Исправления

- Общий popover.ts сохраняет нативный top layer в поддерживающих браузерах. В старых движках тот же список, пометка или toast переносится в текущий dialog; сохраняются цветовые роли и прежний владелец состояния. Проверены повторное нажатие, выбор темы, клавиатура, Escape, outside press и отказ копирования. Порядок возврата фокуса исправлен: Escape больше не открывает пометку заново.
- Document.astro задаёт общий запасной ease-out для движков без CSS linear(). Пружины современных браузеров и физика жестов сохраняются. Обновление новостей использует AbortController с отменяемым таймером и cleanup, без обязательных AbortSignal.any/timeout; проверены тайм-аут, сохранение снимка и успешное повторное обновление.
- Native snap не записывает заново уже достигнутую позицию с допуском одного CSS-пикселя. В Firefox 113 повторная доводка образовывала поток scroll/scrollend и закрывала пометку. Теперь проверяется реальное спокойное состояние ленты, затем открытие пометки. Логика общая для пяти компактных каруселей.
- В старом WebKit у компактной страницы оставался горизонтальный ход 8 px при совпадающих innerWidth/scrollWidth. Нулевые размеры viewport-scrollbar у html/body устраняют его. Вложенные области чтения сохраняют свои полосы прокрутки; ПК-правила не изменены.
- В исходных трёх Manrope отсутствовала привязка U+00A0. WebKit 16.4 рисовал артефакты у неразрывных пробелов. Веб-копии добавляют соответствие существующему пробелу U+0020. Контуры, ширины, shaping, все прежние Unicode-привязки и copyright сохранены; оригиналы остаются в проекте. Генератор prepare-body-fonts.py и body-fonts.json воспроизводят результат, четыре Python-проверки подтверждают преобразование. Изолированный визуальный пример — artifacts/iteration57/font-probe.png.
- Нижняя панель не снимает ненужные геометрические позы при мгновенной подготовке и неизменившемся контексте. Форма, содержимое, согласованная пружина и сохранение фокуса остаются у прежнего dock-surface.ts.

Оптимизация медиа прохода56 сохранена: видео Hero 4 985 368 вместо 7 113 788 байт, та же геометрия/длительность/fps, SSIM 0,990530. Исходные файлы сохранены. Скрытые ПК-новости на телефоне и далёкие постеры видео не загружаются заранее.

## Проверенный срез

Одна неизменённая сборка:

- 93 Node и 10 Python-проверок; Astro check — 101 файл, ноль ошибок/предупреждений/подсказок; собраны пять страниц.
- 16 наборов регрессии, 366 сценариев, включая 85 touch-сценариев, быстрые повторы, отмену и прерывания, чтение отзывов, обе темы, 200% текста, safe-area, низкий экран, загрузки и маршруты записи без отправки.

- Восемь проверок реальных старых движков WebKit 16.4 и Firefox 113.0: телефон 390×844/DPR3, планшет 768×1024/DPR2, ПК 1440×900/DPR1, поворот, настройки, пометки, toast, услуги, FAQ и новости после тайм-аута. Доказательства собраны tests/device-acceptance.py из фактических результатов. Файлы — tmp/planning/iteration57/acceptance-summary.json, regression/verification.json, compatibility-accepted.json и legacy.json. Снимки — artifacts/iteration57. Порядок хеширования одинаков для Python/Node и не зависит от особенностей сортировки путей ОС.

В раннем стресс-прогоне до последних исправлений три последовательности стрелок не дошли до ожидаемого индекса; отдельная инструментированная последовательность прошла. Проверка координат попадания добавлена в текущий runner. После исправлений полный набор, включая быстрые жесты и прерывания, прошёл целиком. Не выдаём диагностические неуспешные прогоны за принятую сборку; исторические отчёты не переписывались.

## Лабораторные замеры

Шесть парных образцов панели: три запуска до/после, в каждом шесть циклов открытия/закрытия. Chrome 390×844, CPU ×4, без параллельных браузерных заданий. Чтения геометрии сократились со 120 до 66, чтения стилей со 120 до 96. Медианы script/layout отличаются мало; измеренный результат здесь — сокращение повторной работы, без заявления прироста FPS или экономии батареи.

Для загрузки выполнены 18 холодных запусков. По три образца на сборку и профиль, окно 8 с, статический HTTP без сжатия, внешние запросы заблокированы. Медленный профиль — CPU ×4, 150 ms RTT, 1,6 Мбит/с. Сравнение с принятой сборкой56:

| Профиль | Медиана LCP до → после | Завершённые байты без MP4, до → после |
|---|---:|---:|
| Телефон | 180 → 164ms | 761033 → 763601 |
| Телефон, медленный профиль | 2268 → 2284ms | 761033 → 763601 |
| ПК | 280 → 296ms | 1350668 → 1353236 |

В этой таблице учтён HTML-документ. Разница2 568 байт включает новые средства совместимости и веб-копии шрифтов. Потоковые байты MP4 исключены: их объём за 8 с меняется от буферизации. Выборка не доказывает общего ускорения LCP. Максимум отдельного interaction-event на медленном профиле — 256 ms; это не полевая INP. Медиана script-простоя за 1,5 с — 0 ms на обычном профиле и около 2,6 ms на замедленном. Видео вне экрана остановлено во всех образцах.

Сырые данные — dock-performance.json, performance.json и performance-summary.json в каталоге прохода. Результаты принадлежат названным локальным условиям. Аппаратные Safari/Android, энергосбережение, GPU, батарея, реальный звук/вибрация и публичные CDN/полевые Core Web Vitals не подтверждаются этой матрицей; аппаратный этап пропущен по решению владельца и не остаётся обязательным блокером локальной задачи.
