## Причина и правка

В трёх первых визитах trace показал одинаковый сдвиг заголовка и описания Hero на 162 px после публикации измеренной высоты cookie-плашки через `--dock-live-height`. `new68initial-layout.py` детерминированно воспроизвёл тот же сдвиг на неизменённом I: полный CSS и шрифты готовы, модули удержаны, затем отпущены. Исходный отрицательный результат сохранён в `artifacts/iteration68/initial-i-red-a/`.

В J геометрия подписи Hero при открытом уведомлении использует штатную высоту панели действий, а не временную высоту cookie. Сохранённая адаптация к реальной высоте toolbar при закрытом уведомлении остаётся у существующего владельца. Компонент MobileNav перенесён перед содержимым страницы: cookie-HTML не должен ждать разбора всей галереи, отзывов и подвала. Экземпляр панели и владельцы согласия, меню и выбранных действий остаются едиными. Изменения пока не опубликованы.

Действующий regression использует задержку только входных HTML-модулей через dynamic import; исходный compiled ESM-граф не меняется. Это геометрическая fixture, а не замер публичной доставки. J проходит 36/36 (320/390/600 × обе темы × первый/повторный визит × три движка): дельта заголовка/описания 0. Артефакты `artifacts/iteration68/compiled-j68-entry-initial-{chromium,firefox,webkit}/results.json`. ## Определение TBT

Из тех же девяти настоящих HTTPS traces рассчитан **timespan TBT от FCP до 10000 ms**: сумма пересечений блокирующих частей long task сверх 50 ms с этим окном. Все образцы покрывают полные 10000 ms; четыре граничных self-check проходят. Это не Lighthouse navigation TBT до TTI и не полевой INP. Определение: https://web.dev/articles/tbt. Анализатор `scripts/analyze-public-load.py`, исходная серия и `timespan-tbt.json` сохранены.

Медианы I: телефон с сохранённым отказом 249 ms, первый визит 223 ms, ПК 0 ms. Окно и формула фиксируются до повторной серии J; последующая разница оценивается вместе с LCP/CLS, без заявления общей скорости по одной метрике.

Штатные read-only проверки интеграций Тильды17 ноября вернули native `activate:no/needregister:yes` для Google/Яндекса. Они не отменяют подтверждённый прямым тегом ownership и сохранённый внешний GSC LIVE/RequestIndex; статусы кабинетов не получены через этот интерфейс. OAuth-переход и повторное добавление счётчиков не выполнялись.
