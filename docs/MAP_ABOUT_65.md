# Карта и About: проход65

Исправления локального кандидата от16.11.2026. Этот отчёт не подтверждает публикацию и не заменяет общий RELEASE_TRACKER.

## Что найдено и изменено

1. При подходе к карте Chrome DevTools записывал огромные Paint clip bounds у всех четырёх карточек About, находящихся примерно на2634px выше viewport. Ограничение paint у самой карты этого не устраняло. `about.css` теперь задаёт `contain:paint` ПК-слоям About. Размеры слоёв, карточек, фотографий, заголовков и их матрицы transform сохраняются. Компактная лента не получает containment. Уровни/перекладывание и источник текста не меняются.
2. `page-motion.ts` повторно назначал шапке уже присутствующий класс `is-floating` на каждом scroll-кадре. Теперь hysteresis сохраняется, а DOM меняется только при действительной смене состояния. Проверка настоящим wheel после установившегося состояния требует ноль повторных записей класса.
3. Начальный белый документ внешнего iframe был виден во время загрузки. `contacts.css` использует существующий `aria-busy` общего loader: ожидающий iframe скрыт сразу и не перехватывает pointer-события, после готовности появляется через общий220ms context-переход. При reduced motion показ мгновенный. Новой логики готовности и второго loader нет; общий timeout также восстанавливает видимость и pointer-события. Вариант без JavaScript сохраняет noscript-карту.

Загрузка карты по-прежнему начинается после видимости и160ms тишины после прокрутки. Обязательная дополнительная кнопка включения карты не добавлена. Источник iframe и адресные ссылки сохранены.

Полноэкранная смена фона в локальном DOM/кадрах не воспроизведена: фон HTML оставался постоянным, CLS в первой диагностике равен0. Сторонний bootstrap Яндекса давал отдельные разрывы RAF после окончания движения; изменение paint-границ не является гарантией скорости сети и кода поставщика.

- `tests/iteration65-map-about.py`:28сценариев на каждый из Chromium, Firefox и WebKit. Полный цикл всех четырёх карточек, реальные wheel-действия и промежуточные RAF, ширины961/1024/1280/1440/1920, высоты720/900/1080, обе темы и reduced motion. Отдельный сценарий действительно удваивает размер текстовых узлов, а не только корневой размер шрифта. В stack-режиме заголовок остаётся на общей координате через все карточки; в flow-режиме не становится sticky.
- `tests/iteration65-map-startup.py`:пока iframe ожидает, opacity=0 и общий loader виден; после load opacity проходит0→1, после timeout карта также не остаётся невидимой. ## Диагностика производительности

`tests/iteration65-map-performance.py` сравнивает один неизменяемый статический build. Baseline возвращает только три прежних поведения в передаваемом браузеру коде/CSS, файлы сборки не редактируются. Изменение шапки восстанавливается только в найденном поточном JS-владельце с проверкой единственности. Порядок baseline/candidate чередуется; каждый образец использует свежий браузер и foreground-страницу. Записываются видимость, назначение src, начало запроса, состояние provider и время после последнего scroll. Медленный/неполученный provider не заменяется удачным образцом.

Первая серия не принята как3-парный benchmark: первый полный парный образец получен, но в следующем образце не произошло подключение iframe в отведённом окне. Стенд доработан для длинного ожидания, foreground и явной диагностики src/видимости. Следующий сырой отчёт сохранён как `map-performance-crossing-window.json`: в нём первый RAF-интервал пересекал начало измерения, отчего один gap оказался больше всей длительности наблюдения. Это дефект измерения, а не доказательство зависания сайта.

Последний полный повтор `map-performance.json` завершился exit0: три пары, шесть свежих Chrome-браузеров, чередующийся порядок, CPU×4, реальный Яндекс, без параллельных browser/compile jobs. Оба конца каждого учитываемого RAF-интервала находятся внутри окна наблюдения. Все образцы сохранены, неудачные не заменялись; каждый iframe реально начал запрос и закончил load. Сборка до/после побайтово неизменна.

| Медиана трёх образцов | Baseline | Кандидат |
|---|---:|---:|
| Огромные main-frame Paint clip bounds |65|8|
| Повторные class-записи шапки |117|0|
| P95 промежутка RAF |8.4ms|8.4ms|
| Наибольший промежуток RAF за образец |208.3ms|145.7ms|

Это локальный причинный A/B на одной сборке. Окно включает подход колесом и bootstrap после видимости; отдельные visibleAt/srcAssignedAt/loadedAt показывают этапы загрузки. Стабильный P95 не улучшился. Уменьшение Paint bounds и лишних DOM-записей подтверждает устранение конкретной работы; нельзя преобразовывать его в обещание ускорения FPS, GPU-экономии или полного отсутствия пауз внешнего поставщика.

Две ранние парные диагностические пробы показали29→5событий с огромными main-frame paint-bound при временном containment. Это границы Paint из trace, не число фактически растрированных пикселей, не GPU-память и не полевой FPS. Производительность поставщика карты и условия сети учитываются отдельно.
