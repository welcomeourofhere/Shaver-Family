# Производительность прохода 65: сохранённый baseline 64 и пакет C

Дата проверки: 16 ноября 2026 года. Приняты 18 независимых холодных загрузок без сжатия и отдельные 6 загрузок с gzip. Первоначальная загрязнённая попытка из 12 samples полностью исключена из расчётов. Чужие browser/CPU jobs во время двух принятых серий не выполнялись.

На медленном профиле телефона gzip-проба дала LCP **1348 → 1548 мс**, то есть остаточную разницу **+200 мс / +14,8%**. Это менее принятого ориентира 2500 мс и приемлемый лабораторный результат кандидата, но регрессия относительно baseline остаётся. Нельзя утверждать, что всё стало быстрее. Десктопная медиана LCP без сжатия сохранилась на уровне 336 мс.

## Одинаковые условия

- Chrome `157.0.8103.52`, отдельный холодный контекст для каждого sample, кэш отключён через CDP.
- Телефон: viewport 390×844, mobile/touch; ПК: 1440×900. Это эмуляция на Windows, не физический телефон.
- Обычный профиль не задаёт сетевое/CPU-замедление. Медленный профиль: CPU ×4, RTT 150 мс, download 200 000 байт/с (1,6 Мбит/с), upload 93 750 байт/с.
- Первоначальная загрузка наблюдается 8 секунд. Внешние запросы блокируются; собственные ресурсы отдаёт локальный HTTP-сервер.
- Затем тот же общий сценарий прокручивает к FAQ, ждёт 700 мс, измеряет 1500 мс простоя; на телефоне открывает меню и закрывает Escape.
- Общий владелец сценария — `tests/device-performance.py`, SHA-256 `c655288c000246ca83f236f431cc0e0380626fa405ad9920e5b749777d2658e3`.

Во всех 24 принятых samples видео Hero останавливалось вне экрана; ошибок JavaScript не было. В мобильном efficient-варианте общий сценарий также проверяет отсутствие загрузки `/media/news/` и отсутствие ранних постеров остальных видео.

Поля доказательств: `fieldData: false`, `physicalDevice: false`, `published: false`. Последнее означает, что команды проверки ничего не публиковали; актуальное состояние публикации фиксируется отдельно. Эти результаты не являются полевыми Core Web Vitals, INP, проверкой физического Safari/Android или измерением публичной страницы со сторонними скриптами.

## Отдельная gzip-проба: 6 samples медленного телефона

Временный helper `.local/release65/native-performance-gzip65.py` импортирует те же `sample`, `serve`, `digest`. Единственная подмена — `Quiet.send_head`: по `Accept-Encoding: gzip` HTML/CSS/JS/MJS/JSON/SVG/TXT/XML передаются gzip; binary/video/font остаются без изменений. Сжатие подготовлено до браузерных samples; HTTP-ответы и распакованные байты отдельно проверены. CPU, сеть, геометрия, 8 секунд, блокировка внешних запросов и все действия общего сценария сохранены. Этот helper не оптимизирует исходники.

Малые серии, последовательный порядок и лабораторный сервер не дают основания превращать эти значения в прогноз полевого LCP.
