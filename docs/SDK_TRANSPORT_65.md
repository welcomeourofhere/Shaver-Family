# Реальный транспорт Метрики и GA4: проход 65

16 ноября 2026 года подготовленный harness выполнил два независимых Chromium-сценария: отдельно Метрика `114263185`, отдельно GA4 `G-TF121LKSEQ`. Оба завершились успешно, ошибок JavaScript — 0. Google/Яндекс SDK и collection-запросы использовали настоящую сеть, без подмены ответов.

**Собственные HTML и ресурсы доставлялись синтетически**: exact C native fixture была отдана локальным route fulfill под `https://soyuz.hair/`. Поэтому результат подтверждает транспорт реальных SDK после настоящего UI-согласия, но не публичную HTML/HTTPS-доставку домена и не приём событий в отчёты кабинетов.

## Выполненный пользовательский сценарий

В каждом из двух свежих контекстов последовательно проверено:

1. Начальная загрузка и видимый баннер: ни одного запроса к распознаваемым службам аналитики до решения.
2. Доверенный клик отказа, затем reload: ни одного запроса; баннер повторно не появляется.
3. Штатная кнопка настроек → cookie: обе службы выключены. Включена только одна соответствующая служба. До нажатия «Сохранить» запросов по-прежнему нет.
4. Доверенный клик «Сохранить»: в собственном consent storage включён ровно выбранный флаг; загружен её настоящий SDK, завершён успешный page_view. Вторая служба не обращается к сети.
5. Настоящий клик записи: успешный `booking_open` должен возникнуть в своей фазе после этого действия; более раннее событие не принимается.
6. Настоящий клик покупки сертификата: новая вкладка закрыта без загрузки магазина; успешный `certificate_open` возникает в соответствующей фазе.
7. Повторное открытие cookie → отзыв: оба собственных флага становятся `false`. Повторный клик записи не отправляет пользовательские цели за 2 секунды наблюдения.

Нажатия были действительными browser/UI click с `event.isTrusted`; harness не диспатчил события аналитики вручную. До их соответствующих действий `booking_open`/`certificate_open` отсутствовали. Успех запроса принимается только после завершения, с 2xx и без `networkFailed`.

## Минимизация доказательств

Сохранены только собственные публичные номера счётчиков, разрешённые имена событий, безопасный путь endpoint, фаза, HTTP-метод/статус, признаки завершения/ошибки и агрегатные счётчики кликов/доставки. Объекты Request удерживались до terminal finish/error и очищены при закрытии контекста.

Не сохранялись visitor/client ID, cookie, полные URL/query, request body, заголовки, generic storage, HAR, trace, тексты консоли или скриншоты. Из собственного consent storage читались только логические флаги двух служб. Публичные номера счётчиков выше не являются идентификаторами посетителя.

## Кабинеты аналитики и непроверенное

Отдельное read-only обращение root к realtime-коннектору GA для property `564405159` вернуло 403 «недостаточно прав». Какой OAuth-аккаунт использовал коннектор и точная причина ограничения, не установлено; права не менялись. Это ограничение чтения через коннектор **не является доказательством ошибки dashboard или collection**. Реальный GA collection в настоящем SDK получил 204; появления данных в интерфейсе GA это само по себе не подтверждает.

В область этого прогона не входят публичная доставка HTML/TLS сайта, корректность всех скриптов Тильды, dashboard ingestion Метрики/GA, физические устройства, реальная запись, оплата, работа карты и юридическая сертификация согласий. Границы `syntheticDelivery: true`, `SDKsStubbed: false`, `dashboardIngestionVerified: false` сохраняются и после успешного результата.
