# Визуальный аудит, проход 65

Дата: 16.11.2026. Это локальная приёмка кандидата, а не подтверждение публикации. Действующая опубликованная версия до переноса кандидата — `db23e622f97223556f77`.

Область: все основные разделы, общая шапка и подвал, интервью, меню, контакты, окно записи и настройки cookie. Проверяются скругления, обрезка, фактическая зона нажатия, размер и перенос текста, расстояния и промежуточные ширины. Увеличение текста до 200% проверяется при неизменном viewport; это отдельный сценарий от browser zoom.

Детальные списки с конкретными кадрами: [телефон и планшет](visual-audit65-mobile.md), [ПК](visual-audit65-desktop.md). Исходные авторские тексты, фотографии, условия услуг и назначения ссылок сохранены.

## Подтверждённые причины и исправления

| Проблема | Причина | Общий владелец и решение |
|---|---|---|
| Срезанный или расширяющийся scrollbar | Прозрачная граница и прежняя логика видимости меняли видимый контур; скругление окна обрезало верхушку | `system.css` и MaterialSurface: постоянная нативная полоса 4px, без idle/proximity-логики; меняется только цвет. В Firefox используется стандартный `thin`. Подробности в SCROLLBARS_65.md |
| Заголовок Честной цены становился обычным текстом около 961px | Container query включался раньше viewport query, в котором определялся размер | `first-visit.css`: размер использует существующий `--size-40`, доступный в обоих режимах |
| У интервью появлялась отдельная строка с точкой | Постоянный правый отступ под крестик сужал все строки | `master-story.css`: место под крестик резервируется только на его высоту; следующие строки получают полную ширину |
| Крестик интервью терялся в тёмной теме | Локальный фон панели перекрывал фон общей icon-button, но оставлял тёмный foreground | Удалено локальное перекрытие фона; используется общая жёлтая кнопка окна с согласованными состояниями |
| Обложка срезала головы на коротком экране | Фиксированная высота в `svh` и `object-fit:cover` | Обложки всех шести интервью сохраняют исходное соотношение 4:3. Изображение участвует в обычном потоке и прокручивается вместе со статьёй |
| Название услуги налезало на цену при 200% текста | Цена получала отдельную grid-колонку, а длинное слово не помещалось в оставшуюся | `service-deck.css`: гибкая строка с переносом цены ниже, без уменьшения текста и полей |
| Кнопки мастеров обрезались при 200% текста | Полная/короткая подпись выбиралась только по viewport | Существующий `action-label.ts` измеряет фактический текст и ширину кнопки. Полное доступное имя с именем мастера сохранено |
| В личных контактах поля фотографии и текстовые группы расходились | Центрирование квадратного фото и независимые 44px строки создавали разные отступы | Фото растягивается по высоте строки с равными полями8px, текст получает свой внутренний ритм. Телефон и Telegram стоят рядом по вертикали с8px между видимыми строками; минимальная зона44px сохранена |
| Имена контактов дробились при 200% текста | Фиксированное фото оставляло слишком узкую колонку | Intrinsic flex-компоновка переносит текст ниже фотографии, когда слова не помещаются рядом. В нормальном размере сохраняется прежняя композиция |
| Шестерёнка перекрывала часть ссылки на политику внизу узкого ПК | Нижнего свободного места было меньше фиксированной кнопки | Подвал резервирует место под глобальные угловые действия; ссылки и кнопки имеют независимые зоны нажатия |
| Ссылки подвала пересекались при 200% текста | Фиксированные доли колонок не учитывали полную подпись | Навигация переносит целые ссылки; документы используют доступную ширину в нижней строке |
| Серый placeholder выходил за ширину при 200% | Длинное слово задавало min-content ширину grid-ячейки | Intrinsic min-width и перенос слова принадлежат placeholder, без скрытого изображения или blur |
| Проверка видела устаревший CSS после сохранения | Нативные уведомления файлового watcher на рабочем диске не инвалидировали Vite cache | В dev-конфигурации включён polling. Проверен HTTP-ответ после изменения файла уже после запуска сервера; production-код от polling не зависит |

Последующие уточнения владельца расширили проход: общий нижний RailControls Hero, цветные плашки постов, «Знакомство», зеркало расположения сертификатов, единый hover-popup шапки со статусом, сокращённый cookie-текст и общий FAQ-аккордеон, Lucide-иконки, «Знание — сила!», две колонки личных контактов. Это заменяет соответствующие промежуточные варианты. Заголовки в тёмной теме остаются жёлтыми; только scrollbar получает стандартный красный вместо розового. Подробные доказательства — HERO_AND_CERTIFICATES_65.md, UTILITY_ICONS_65.md, header-text-fit65.md и COOKIE_SETTINGS_65.md.

Приёмка контактов и подвала охватывает11 ширин320–1920px, обе темы и увеличение текста до200% в Chromium/Firefox/WebKit. Реальные фотографии декодируются перед визуальной фиксацией. Проверяются поля фото,8px между строками связи, две карточки при доступных700–960px, левая граница контактов подвала, компактная высота, полные юридические ссылки, отсутствие обрезки и независимые роли тёмной палитры. Итоговые JSON фиксируют конкретную замороженную версию; публичная приёмка остаётся отдельным этапом.

## Проверки и ограничения

- `tests/iteration65-visual-fixes.py`: обложки всех шести интервью, контраст крестика, отсутствие одинокой пунктуации, отступы контактов, пересечение фиксированных кнопок со ссылками и увеличенный текст услуг. Геометрия измеряется в браузере и сохраняются реальные viewport PNG.
- `tests/iteration65-team-labels.py`: 120 сочетаний трёх движков, размеров и тем; 720 кнопок с одной строкой, сохранёнными полями и областью нажатия.
- `tests/iteration65-shell.py`: общие элементы, placeholder/сертификат, геометрия настроек, полные документы, 200% текста и отсутствие горизонтального выхода.
- Нативный экспорт и опубликованный сайт проверяются после сборки того же manifest. Локальный HMR не заменяет эти проверки.
- Снимки, искажённые CDP-захватом длинного элемента, не считаются дефектом продукта. Для спорных мест повторяется обычный viewport-кадр.
- Физические телефоны исключены владельцем из текущей задачи. WebKit на Windows не является проверкой физического Safari. Полнота обхода не означает доказательство отсутствия всех возможных ошибок.
