# Доступ к полным альбомам: проверенная причина отказа

16.11.2026. Владелец правильно создал ключ сообщества с правом «Фотографии». Дополнительная серверная диагностика подтвердила действительность этого ключа и разрешение `photos`, setting4. Повторно создавать такой же ключ или добавлять остальные права не требуется. Предыдущая рекомендация создать community key до проверки совместимости метода была ошибочной.

Официальная схема `VKCOM/vk-api-schema/photos/methods.json` для `photos.getAlbums` и `photos.get` перечисляет только `user` и `service`, без `group`. При этом наличие типа в схеме не гарантирует доступ конкретного профиля приложения к методу.

Run [43884096542](https://github.com/welcomeourofhere/Shaver-Family/actions/runs/43884096542), commit `f1dc7bee07b3118796fd049ec9bc9cdecd2cd10e`, job133357417099 завершён успешно. Это успех диагностики, не успех выгрузки альбомов. Ветка `codex/soyuz-photos-read`, main и production-source branch не изменялись. Защищённые значения оставались только в Actions env. Ни пользовательские сведения, ни raw response/request_params в журнал не выводились.

| Подключение / метод | Фактический ответ |
| --- | --- |
| Существующий `VK_TOKEN` / groups.getTokenPermissions | 28, `method is unavailable with service token` — подтверждает сервисный тип |
| Существующий `VK_TOKEN` / account.getAppPermissions | 1051, `Method is not available for this profile type` |
| `SOYUZ_VK_PHOTOS_TOKEN` / groups.getTokenPermissions | Успех, photos setting4 |
| Существующий `VK_TOKEN` / photos.getAlbums | 1051, `Method is not available for this profile type` |

Методы фиксированы, read-only, без повторов/редиректов; тело ограничено1MiB. Самопроверки очистки сообщений выполнены до сетевого шага. В GitHub UI просмотрены только названия двух существующих repository secrets; других настроенных ключей там нет. Содержимое не читалось и не заменялось.

Полный album-reader остаётся недоступен с этими двумя подключениями. Следующий допустимый путь — существующее разрешённое подключение приложения/пользователя либо штатная авторизация владельца в подходящем приложении ВК. Без подтверждённого доступа нельзя обещать успех, создавать чужое OAuth-подключение или выдавать снимок стены за полный экспорт. Кабинет ВК ограничен браузерным инструментом; альтернативные браузерные endpoints, session cookies и обход этого ограничения не используются.

Источник доступных фотографий текущего сайта — проверенный `vk-public-wall`; происхождение и размеры описаны в `VK_WORK_PHOTOS_66.md`. Значение1051 теперь приводится по фактическому очищенному ответу API, а не как выдуманная расшифровка из публичного errors.json, где этого кода нет.
