# Публикации ВК в Hero

05.11.2026. Группа `soyuz_kirov`, владелец стены `-210007626`. Используется официальный публичный Community Widget ВК: начальная десятка плюс его публичное «ещё». Снимок сортируется по дате, поэтому старое закрепление не вытесняет свежие публикации. Выбираются10последних записей, включая текстовые. Выдуманных новостей/фотографий нет.

## Локальное обновление

```powershell
python -X utf8 scripts/update-vk-news.py
python -X utf8 -m unittest discover -s tests -p vk_news_test.py
```

Нужен установленный Pillow; используется тот же локальный экспорт изображений, что в остальных скриптах проекта. Новых зависимостей сайта нет. Ключи, вход в аккаунт и закрытые API не требуются. Временная форма ключа закрыта; интеграция с ней удалена после выбора публичного обновления.

Worker читает только `vk.ru` и разрешённые CDNфото `.userapi.com`/`.vkuserphoto.ru`; перенаправления за эти границы блокируются до перехода. Ограничены размер ответа, разрешение и размеры изображения. Источник не исполняется: HTMLразбирается стандартным HTMLParser, в сайт попадают только plain text, проверенные ссылки на нужную стену и локальные WebP. Кнопка провайдера «Показать ещё» исключается отдельно, сохраняя пробелы исходного текста.

Из доступного списка `as` выбирается версия до1280px, без искусственного увеличения. WebP640/1280(либо реальный меньший оригинал), quality88; имя включает IDпоста и хеш доставляемого WebP. Хеш исходника хранится отдельно в метаданных. Если у записи нет подходящего фото, сохраняется её текстовая карточка. Фотографии не подменяются несвязанными кадрами.

Результат: `content/news.json`, его идентичная публичная копия `public/data/news.json`, файлы `public/media/news`. Изображения экспортируются до замены JSON; ошибка источника оставляет предыдущий снимок. Более старые медиа сохраняются для уже открытых/закешированных страниц.

## Сайт

Astro сразу выводит последний локальный снимок — первая фотография загружается с высоким приоритетом, следующая подготавливается перед автосменой. Остальные картинки декодируются по необходимости. Слайды меняются затуханием; быстрые действия отменяют устаревшую загрузку. Во время чтения, ручного управления, вне viewport, при скрытой вкладке и reduced motion автосмена остановлена. Медленный зум фотографии независим от паузы переключения; вне видимости и при reduced motion он тоже останавливается.

Лозунг над всей композицией имеет3строки. Внизу фотографии постоянно видна общая тёмная стеклянная панель: дата, короткий текст и центрированные индикаторы. Общая широкая ссылка ВК раскрывается при hover/focus текстовой панели, на телефоне доступна сразу. Её цвета — красный/синий/жёлтый, соседние и крайние в цикле различаются. Суммарная ширина индикаторов неизменна; сверху/снизу точек равные19px с сохранением44px цели нажатия. Края фото переключают пост и мягко затемняются/размываются по hover/focus; стрелок и верхней иконки нет.

## GitHub — подготовлено, не включено

`.github/workflows/update-vk-news.yml` готов обновлять публичный снимок ежедневно в03:00UTC и вручную. Workflow, push и удалённый репозиторий в этой работе не запускались и не создавались: текущий этап локальный.

После согласованного размещения можно указать rawURL`public/data/news.json` в `content/site.json:newsFeedUrl`. Сайт проверяет схему, группу, уникальностьID, ссылки и пути медиа перед обновлением. Относительные `../media/news/…` корректно разрешаются как локально, так и в GitHub raw. Ошибка сети/невалидная лента сохраняет SSRснимок. Секреты GitHub для публичного способа не нужны.

Публичная HTMLструктура может измениться на стороне ВК; тогда job завершится ошибкой и сохранит прежние новости. Контакты заведения не изменяются по текстам публикаций: их источник — последние подтверждения владельца.
