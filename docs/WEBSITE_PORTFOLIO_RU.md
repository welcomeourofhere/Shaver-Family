# Утверждённая подача портфолио СОЮЗа

Владелец принял подачу 17.11.2026. Это основа для дальнейших обновлений. Текущий комплект показывает локальную версию сайта на дату съёмки; он не подтверждает состояние опубликованного релиза.

## Что сохранено

- Девять квадратных изображений 1600 × 1600 px, JPG для ВК и PNG без потерь.
- Порядок: главная, услуги, команда, работы, акции, отзывы, контакты, мобильная адаптация, две темы.
- Фирменные кремовый, синий, жёлтый и графитовый фоны; заголовки Manrope, счётчик справа.
- Крупные прямоугольные окна сайта; компактное окно перекрывает десктопное. Лёгкая браузерная рамка, без корпуса телефона и толстого контура.
- На обложке и разделах сохраняется согласованная крупность. В контактах компактное окно слева, у команды — ниже и правее. На восьмом кадре три мобильных экрана; на девятом один мастер в двух темах.
- Только существующие заголовки и номера. Нижние пояснения и новый рекламный текст не добавлять.
- Снимки сохраняют пропорции. Элементы страницы по контурам не вырезаются. Видимые соседние карточки — часть реального интерфейса.

## Где лежат файлы

- Утверждённый комплект: `output/vk-portfolio-selected-refined-2026-11-17/`.
- JPG для поста: `SOYUZ-SELECTED-REFINED-9-slides.zip` в этой папке.
- Самостоятельный шаблон: `presentation/website-portfolio/`.
- `render.py` — композиции, размеры, прямоугольные области десктопных кадров и экспорт.
- `screens/` — 16 исходных снимков; `assets/` — две копии шрифта и зафиксированная палитра. Зависимостей от прошлых экспериментальных папок и текущих токенов сайта у шаблона нет.
- `baseline.json` — дата принятия и SHA-256 исходников/утверждённых PNG.
- `verification.json` — проверка точного воспроизведения всех девяти кадров.
- `portfolio.html` в экспорте — готовый автономный просмотр со встроенными изображениями и шрифтами.

## Повторный экспорт

Из корня проекта, в установленной среде Python с Pillow, Playwright и Google Chrome:

```powershell
python presentation/website-portfolio/render.py --output output/vk-portfolio-YYYY-MM-DD
```

Нужно указать новую, ещё не существующую папку. Скрипт отказывается перезаписывать прежний экспорт. Он создаёт 9 JPG, 9 PNG, общий лист, уменьшения, автономный HTML, ZIP с девятью JPG и протокол проверок. Для экспорта сохранённых снимков работающий сайт не требуется.

## Обновление после изменений сайта и релиза

1. Сохранить текущий мастер-архив. Для новой версии скопировать папку шаблона в отдельную папку с датой, чтобы сохранить принятую основу и её исходники.
2. Снять обновлённый сайт и заменить соответствующие файлы в копии `screens/`, сохраняя имена и смысл кадров. До релиза источником может быть локальная версия с явной пометкой; релизный комплект сверять с фактически опубликованной версией. Не смешивать разные условия акций и состояния сайта в одном комплекте.
3. На ПК исходный viewport — 1440 × 1000 CSS px, DPR 2. Компактные кадры и темы повторять по сохранённым размерам ниже; темы должны показывать одного мастера с одинаковой прокруткой. Акции показывают настоящее раскрытое условие, без внесения текста в снимок. Не создавать реальную запись или оплату для съёмки.
4. Выполнить экспорт в новую папку. Посмотреть все девять кадров целиком и в уменьшении: заголовки, кнопки, лица, верх/низ окон, перекрытия, актуальность цен и условий, соответствие светлой и тёмной тем.
5. Если геометрия сайта изменилась, поправить только необходимый прямоугольный crop или положение окна. Текущие десктопные crop: x110–1330 CSS px; высота команды888, акций920, отзывов960, остальных1000. Проверки рамок не доказывают смысловую корректность crop — её нужно посмотреть отдельно.
6. Для нового содержимого сформировать новый протокол и хеши, не выдавая совпадение со старым baseline за обязательное условие. Сохранить отдельную версию и JPG-архив. Общую подачу не пересматривать без нового поручения владельца.

Автоматическое наблюдение за релизом не настроено. Обновление выполняется отдельной задачей после появления новых экранов.
