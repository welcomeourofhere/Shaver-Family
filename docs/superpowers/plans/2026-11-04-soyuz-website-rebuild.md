# Новый сайт «СОЮЗ» — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task after the owner approves it. Steps use checkbox (`- [ ]`) syntax for tracking. Подзадачи выполняются последовательно; делегирование этим планом не предписано.

**Goal:** Создать современный сайт «СОЮЗА» с самостоятельным визуальным стилем, понятным выбором услуги и мастера, достоверными данными и реальной онлайн-записью.

**Architecture:** Статически собираемые страницы, общие компоненты, отдельные структурированные данные и небольшие модули поведения. Брендбук остаётся внешней библиотекой оригиналов; в сборку входят только выбранные веб-ресурсы. CRM и запись сохраняют свою внешнюю границу.

**Tech Stack:** Предлагаются Astro со статическим выводом, TypeScript, обычный CSS, нативные HTML-элементы и небольшие клиентские скрипты. Решение о стеке принимается при согласовании плана с проверкой ограничений публикации в этапе 1; установка сейчас не выполняется.

**Spec:** `docs/PROJECT_BRIEF.md` — прямые требования пользователя, включая уточнение о свободе нового дизайна.

Статус: план согласован, локальная реализация начата 4 ноября 2026. Первые три упрощённых концепции отклонены владельцем. Последняя корректировка: меню по примеру Shaver Family, херо одновременно с фото/УТП/скидкой первого визита/кешбэком, более глубокие и функциональные разделы. Текущая работа продолжает один расширенный вариант; прежнее предложение трёх направлений ниже сохранено как история решения. Актуальное состояние — docs/PROGRESS.md.

## Обязательные ограничения

- Существующие наброски — контекст, без обязательств сохранять композицию, оболочку, цвета блоков или механику. Новые решения не ограничиваются прежними попытками.
- Брендбук не копируется целиком и не становится публичной папкой сайта.
- Shaver Family — пример задач и разделов; его архитектура и визуальная оболочка не переносятся автоматически.
- Слоганы, декоративные подписи, технические и демонстрационные комментарии не входят в продуктовый интерфейс.
- Рабочие названия, существенные условия услуги, доступные имена и сообщения восстановления после ошибки остаются понятными.
- Кнопки: одна строка, без обрезки и многоточия; горизонтальные поля не меньше 12 px и область нажатия не меньше 44 px. При недостатке места меняется компоновка.
- Любые сведения о ценах, команде, отзывах и акциях имеют источник. Данные из старых файлов не признаются актуальными автоматически.
- При реальной записи сайт не обещает подтверждение до подтверждения системой записи.
- Персональные данные клиентов, внутренние документы, секреты и CRM-выгрузки не попадают в публичную сборку.
- Публикация и внешние изменения не входят в одобрение локальной разработки.

## 1. Что установлено при подготовке

### Текущий проект

В корне находятся `index.html`, пять файлов CSS, `js/app.js`, `js/data.js`, `js/products.js`, ресурсы и скрипты импорта/снимков/извлечения каталогов. Git-репозиторий и `package.json` на момент проверки не обнаружены. Это не готовая компонентная база, поэтому предлагается новая организация исходников в той же папке.

Среди файлов вне `.agents` насчитано 1159 файлов примерно на 2,08 GB, включая уже скопированные ресурсы. Поэтому до нового импорта нужно проверить совпадения и не создавать вторую полную копию.

В исходниках обнаружены риски:

- Контакты и сведения об акциях повторяются в HTML и JS; присутствуют два адреса и несколько телефонов. Их назначение и актуальность требуют сверки.
- Обработчик `quick-booking-form` отменяет отправку и показывает подтверждение без сетевого запроса. Этот сценарий нельзя переносить в новый сайт.
- Скрипты импорта содержат старые пути `d:/Soyuz`; фотографии отбирались широкими условиями и копировались пакетно.
- Существующие значения цветов и ограничения скруглений неоднородны. Новый набор токенов должен иметь одного владельца.

Это выводы по исходникам. Текущий сайт не прошёл браузерный аудит в этой задаче: доступ из доступного встроенного браузера к локальному серверу завершился тайм-аутом, подключённый Chrome недоступен. Дизайн новой версии не зависит от сохранения старого экрана.

### Брендбук

Корень: `J:/Brandbooks/brand book СОЮЗ Барбершоп 2025`.

Проверены структура библиотеки, стартовый навигатор, визуальный обзор 19 страниц руководства, страница палитры, состав шрифтов, встроенные превью семи вариантов сайта и девяти мобильных первых экранов. Полный покадровый отбор фотографий ещё предстоит.

В руководстве на странице 9 указаны веб-цвета:

| Роль в брендбуке | HEX |
| --- | --- |
| Бежевый | `#F6E8D3` |
| Красный | `#C42F2A` |
| Жёлтый | `#FFCC29` |
| Серый | `#4B4B4D` |
| Синий | `#52658C` |

Отдельная PNG-палитра визуально отличается от чисел руководства. Для исходных токенов использовать явно указанные HEX из руководства; современные производные для фонов, текста и состояний документировать отдельно и проверять на контраст.

Фирменные шрифты — Molot и Manrope; есть веб-версии. Предлагаемая интерпретация: Manrope для интерфейса, Molot для ограниченного выразительного акцента. Логотип не переделывать типографическим набором. Уточнить условия веб-использования файлов перед выпуском.

В библиотеке есть реальные интерьеры, работы, команда, фотосеты 2022 и 2025 годов. Неподписанные портреты не получают имена по внешности. Папки «Не исопльзовать», «Требует уточнения», ранние версии и внутренние документы исключаются из автоматического отбора.

### Shaver Family

В `src/site/html/fragments` найдены блоки первого экрана, подарков и сертификатов, новостей, предложений, услуг, товаров, мастеров, обучения, отзывов, моделей, информации о компании и контактов.

Использовать эту базу для проверки полноты пользовательских задач. Каждый раздел «Союза» должен иметь собственное основание: услуги, которые действительно предлагаются, материалы и способ поддержки актуальности. Копирование всего набора сделает новый проект сложнее без подтверждённой пользы.

## 2. Предлагаемая структура сайта

Первый выпуск: содержательная главная с прямыми переходами к ключевым разделам и отдельные страницы только там, где у пользователя есть самостоятельная задача.

| Раздел | Что помогает сделать | Содержание и поведение |
| --- | --- | --- |
| Шапка и первый экран | Понять, куда попал, и начать запись | Логотип, название/тип заведения и город, сильный реальный кадр, «Записаться», компактная навигация; адрес по месту в композиции |
| Услуги и цены | Выбрать подходящую услугу | Название, цена или честный диапазон, длительность при достоверных данных; категории только при достаточном количестве услуг |
| Мастера | Выбрать конкретного специалиста | Актуальные имя и портрет, подтверждённая специализация при необходимости, связанные работы, запись к мастеру |
| Работы | Оценить результат | Отобранные реальные стрижки/бороды; просмотр крупнее, без бесконечной карусели и выдуманной атрибуции |
| Пространство | Оценить место | Короткая фотогалерея интерьера и процесса; можно объединить с работами, если отдельный блок не даёт пользы |
| Отзывы | Проверить репутацию | Источник и ссылка на площадку; рейтинг/число отзывов показывать только с проверенной актуальностью и способом обновления |
| Контакты | Найти вход, построить маршрут, связаться | Действующие адреса, часы, телефон, понятная схема входа/фото при наличии; карта загружается без блокировки основного содержания |
| Подвал | Найти документы и официальные каналы | Реквизиты и обязательные документы по фактическим сценариям сайта, каналы связи |

Условные коммерческие разделы, предусмотренные планом, но зависящие от подтверждения предложения:

| Раздел | Условие включения | Объём |
| --- | --- | --- |
| Сертификаты | Есть действующие номиналы, правила и процесс приобретения | Компактный блок; отдельная страница при самостоятельном сценарии |
| Лояльность и предложения | Подтверждены механика, срок и ограничения | Одна понятная актуальная точка входа; старые акции не наследуются |
| Товары | Есть актуальные ассортимент, цены и способ получения | Небольшая витрина и при необходимости `/products/`; без корзины и оплаты до отдельного согласования торговли |
| Подробности услуги | Нужны для выбора либо подтверждён отдельный поисковый спрос | `/services/[slug]/`; только самостоятельное полезное содержание |
| Профиль мастера | Есть достаточно работ и сведений | `/masters/[slug]/`; иначе достаточно карточки на главной |

Новости, блог, академия, франшиза, вакансии, запись моделей и личный кабинет не добавляются по аналогии с другим сайтом. Они включаются при подтверждённой задаче, владельце содержания и материалах. Это предложение состава первого выпуска, которое владелец может изменить при согласовании.

Предлагаемая навигация компьютера: «Услуги», «Мастера», «Работы», «Контакты», «Записаться». Дополнительные коммерческие страницы занимают отдельное место только при включении в выпуск. На телефоне — логотип, меню и доступная запись; закреплённое нижнее действие используется, если проверка покажет пользу без перекрытия содержания и клавиатуры.

## 3. Три самостоятельных направления дизайна

Это новые концепции, а не три изменения цвета старого макета. Общими остаются реальные данные и задачи. Сравнение проводится на одинаковом содержимом.

| Направление | Шапка и первый экран | Мобильная композиция | Что проверяем |
| --- | --- | --- | --- |
| A. Светлая фотогалерея | Спокойная светлая оболочка, компактная шапка, одна крупная фотография процесса, ясная запись; красный концентрируется на действиях и марке | Отдельный портретный кадр, читаемая навигация, действие в естественной зоне досягаемости | Узнаваемость без декоративного шума и скорость перехода к услуге |
| B. Современная фирменная афиша | Выразительная асимметрия, крупный знак и дозированный Molot, красная плоскость рядом с реальным кадром; чёткие геометрические отношения | Вертикальная композиция строится заново, сохраняет характер без уменьшения десктопа | Удаётся ли усилить характер бренда, сохранив спокойное чтение и удобную запись |
| C. Графитовая фотосцена | Тёмная нейтральная оболочка, фотография рабочего процесса и аккуратная светлая типографика, точечный красный акцент | Короткий первый экран с безопасным кадрированием лица и рук; доступная запись без полноэкранного тупика | Контраст, доверие к реальным фотографиям, удобство следующего шага и продолжения страницы |

Для каждого направления подготовить шапку, первый экран, открытое мобильное меню и фрагменты услуг/карточки мастера. Так будет видно, работает ли идея за пределами красивой обложки. Опорные размеры сравнения: 1440×900 и 390×844, дополнительная проверка 360 px и промежуточной ширины.

Затем владелец выбирает направление либо формулирует конкретную комбинацию удачных решений. Комбинация получает общую типографику, геометрию и палитру. После этого уточняется визуальная спецификация; полный сайт не разрабатывается сразу в трёх версиях.

В интерфейсе не используются объяснения концепции, «UX/DX/AX», номера вариантов и технические подписи. Эти сведения остаются в документах и средстве сравнения.

Свойства Linear и Apple применяются как критерии: ясная иерархия, предсказуемые действия, быстрый отклик, аккуратные состояния. Прямое копирование их оформления не определяет стиль «Союза». Стек сам по себе не обеспечивает качество.

## 4. Работа с брендбуком и данными

### Ресурсы

Поток: **оригинал в брендбуке → отбор → проверка → веб-экспорт → ссылка из данных → сборка**.

- Читать оригиналы на J: без изменения или перекладывания библиотеки.
- Сначала проверять уже имеющийся `assets`: пригодный экземпляр можно использовать после сверки источника и хеша.
- Отбирать небольшой пакет по роли: логотип, favicon, реально используемые начертания, кадры первого экрана, портреты действующих мастеров, лучшие работы, интерьер.
- В проект включать SVG, WOFF2 и оптимизированные растровые версии выбранных кадров. PSD/CDR/AI, архивы, исходные видео и вся фотосессия остаются вне сайта.
- Для CDR сначала использовать встроенные превью при исследовании; выпускной экспорт получать из векторного оригинала подходящим инструментом, а не растягивать превью.
- Подготовить разные кадрирования для широкого и узкого экрана. Не обрезать лицо, руки и результат работы ради одинаковых карточек.
- Задать размеры изображений, `srcset`/`sizes`, приоритет первого кадра и отложенную загрузку остальных. Видео добавлять только при доказанной пользе и с постером.
- В `content/assets.json` хранить ID, относительный путь источника от корня брендбука, хеш оригинала, пути веб-версий, размеры, назначение, кадрирование и доступную атрибуцию/право использования. Реестр служит сборке и проверкам, а не публикуется автоматически.
- Абсолютный путь к внешнему корню задаётся локальной настройкой. Публичная сборка не ссылается на `J:`, `file://` или символьную ссылку на библиотеку.
- Пересборка сайта использует уже подготовленные веб-ресурсы и не зависит от подключённого диска с брендбуком; повторный экспорт использует оригиналы.

### Сведения о бизнесе

Брендбук — источник брендовых материалов и исторических сведений. Актуальные операционные данные требуют отдельного подтверждённого источника.

| Данные | Источник и правило |
| --- | --- |
| Идентичность, логотип, шрифты | Брендбук с фиксацией выбранной версии |
| Услуги, цены и длительность | XLS/CSV брендбука как исходная справка; затем сверка с действующим прайсом или разрешённым чтением системы записи |
| Мастера и соответствие портретов | Подписанные исходники и подтверждённый действующий состав; никаких имён по визуальному сходству |
| Адреса, часы, телефоны, каналы | Официальные действующие сведения, назначение каждого телефона/филиала |
| Акции, сертификаты, лояльность | Подтверждённые правила, даты и исключения; поле статуса скрывает завершённые предложения |
| Отзывы | Проверенная площадка; ссылка, дата проверки и поддерживаемый способ обновления |
| Товары | Актуальный ассортимент и цены «Союза»; данные Shaver Family не подменяют их |

У записей есть стабильные ID; связи «мастер → работа» и «услуга → запись» задаются ID, а не индексом в массиве и не совпадением названий файлов. Источник и дата проверки хранятся отдельно от видимого текста. Если актуальные сведения недоступны, блокируется только соответствующее наполнение/интеграция, а независимые части продолжаются.

## 5. Простая архитектура и опыт сотрудника

Предлагается Astro, поскольку здесь нужен преимущественно содержательный сайт со статическим HTML и локальными интерактивными элементами. Стандартные компоненты и маршруты предпочтительнее собственного HTML-сборщика. TypeScript проверяет связи данных; обычный CSS задаёт токены и компоновку. React, Next.js, глобальный менеджер состояния, база данных, Supabase/Prisma и WebGL не требуются для согласованного базового сценария.

Перед установкой проверить, где сайт будет размещаться: домен/подкаталог, обычный статический хостинг или ограничения существующей платформы, допустимый JS, пути ресурсов, заголовки и маршруты. Если нужен специфический экспорт для Tilda либо иной платформы, сначала подтвердить совместимость небольшой сборкой и скорректировать именно способ доставки. Не предполагать Tilda по аналогии с Shaver Family.

```text
  dist/                             только результат сборки
  archive/legacy/                   одна сохранённая старая версия, вне сборки
```

Это карта ответственности, а не требование заранее создать пустые файлы. Маршруты услуг, мастеров, сертификатов и товаров появляются по условиям раздела 2. Параметры команд и версии закрепляются после проверки среды в этапе 1.

Основное содержание должно приходить в готовом HTML, а не появляться исключительно после выполнения JavaScript. Компонент владеет собственными состояниями и стилями; страница — порядком блоков. Контакты, цены и подписи не дублируются в шаблонах, метаданных и обработчиках.

Для AX нужен короткий поддерживаемый процесс: сотрудник меняет цену или активность мастера в одном месте, запускает проверку и видит локальный результат. Администратору не нужно редактировать HTML, искать одну цену в трёх файлах или вручную подгонять размер изображения. На первом выпуске это структурированные файлы и инструкция; удобство реального ответственного проверяется на практике. Если нужен редактор без файлов, это отдельная явно определённая потребность, а не скрытое обещание существующей CMS.

| Решение | Польза для UX | Польза для DX | Польза для AX |
| --- | --- | --- | --- |
| Один источник услуг | Одинаковые цены в списке и деталях | Отсутствие ручного дублирования | Одно изменение вместо нескольких |
| Внешняя система записи | Реальное время и доступные мастера | Нет собственной логики бронирования | Нет второго журнала записей |
| Реестр ресурсов | Качественные быстрые изображения | Проверяемые зависимости | Понятная замена кадра без поиска по архиву |
| Общие компоненты | Одинаковое поведение управления | Исправление в одном месте | Предсказуемый результат обновления |
| Минимум отдельных страниц | Короткий путь к действию | Меньше поддерживаемых маршрутов | Меньше мест с устаревшими данными |

## 6. Контракты взаимодействий

| Действие | Обещание интерфейса | Проверка |
| --- | --- | --- |
| «Записаться» | Открывает действующий сценарий записи; ничего не подтверждает самостоятельно | Правильный получатель и адрес, без отправки персональных данных |
| Запись из услуги/карточки мастера | Передаёт выбор, только если система поддерживает официально проверенные параметры | Соответствие ID и фактического результата; иначе честный общий переход |
| Недоступен виджет | Сохраняется прямая ссылка и телефон; ошибочное подтверждение не появляется | Имитация отказа стороннего ресурса |
| Мобильное меню | Открывается с клавиатуры и касанием, закрывается Escape и выбором пункта, возвращает фокус | Фокус, прокрутка, повторное открытие, переход к якорю |
| Просмотр работы | Изображение открывается крупно и закрывается с сохранением места и фокуса | Клавиатура, телефон, возврат к исходной карточке |
| Фильтр услуг | Результат соответствует категории, управление остаётся видимым | Пустая категория, длинное название, повторный выбор |
| Маршрут и звонок | Используют правильный адрес/телефон выбранного филиала | Проверка сформированных ссылок без звонка/внешней отправки |

Не строить собственную форму сбора телефона, если её задача полностью решается системой записи. Не добавлять звуки нажатий и искусственные задержки. Движение помогает понять смену состояния и учитывает уменьшение анимации.

## 7. Навыки и условия применения

Навыки выбираются по этапу, без одновременного применения всей установленной библиотеки. Перед первым использованием конкретного навыка исполнитель читает его `SKILL.md`. Прямые требования владельца имеют приоритет над эстетическими предпочтениями навыков.

| Навык | Когда применяется | Ожидаемый результат |
| --- | --- | --- |
| Ponytail full | Архитектурные решения, код, исправления и ревью | Самое простое полное решение без сокращения требований |
| writing-plans → executing-plans | Подготовка и исполнение согласованного плана | Задачи с результатом и проверкой, прозрачный статус |
| design-first-ui-prompting, frontend-design | Три концепции, затем спецификация выбранной | Композиция и характер до полного написания страницы |
| apple-design | Типографика, отклик, слои и поведение управления | Спокойный понятный интерфейс с уместным движением |
| no-ai-design-slop | Проверка концепций и новых блоков | Отсутствие случайных карточек, декоративных пояснений и универсальных шаблонов |
| ui-ux-design-system, modern-css-html | Выбранные токены и компоненты | Единая система и нативные возможности браузера |
| interaction-contracts | Меню, запись, галерея, фильтры | Однозначные переходы, ошибки, возврат и фокус |
| better-writing | Навигация, действия, состояния и содержимое | Короткий конкретный текст без потери существенных условий |
| design-for-repetition | Обновление прайса, команды и фотографий сотрудником | Проверенный повторяемый процесс без ручного дублирования |
| mobile-native, accessibility, break-ui | Мобильная компоновка и проверка крайних случаев | Доступное управление, длинные названия не ломают экран |
| animation-performance | Только если добавлено движение | Движение укладывается в бюджет и отключается по предпочтению пользователя |
| core-web-vitals, fixing-metadata | Подготовка собранного сайта | Измеренная скорость, корректные метаданные и индексируемые страницы |
| agent-browser или доступный браузерный инструмент | Прототипы и собранный сайт | Настоящие снимки, проверка действий, ошибок консоли и разных ширин |
| verification-before-completion | Перед сдачей каждого результата | Свежие доказательства вместо деклараций |
| pdf, средства чтения таблиц/документов | Исследование конкретных исходников | Корректное чтение нужного формата без массового переноса |
| storefront-best-practices | Только если включён раздел товаров | Проверяемые цена, наличие и получение, без фиктивной покупки |
| seo-workflow | Если утверждены самостоятельные поисковые страницы | Подтверждённые темы и полезные страницы вместо наполнения ради ключевых слов |
| systematic-debugging, security-review | При воспроизводимой ошибке или появлении соответствующей границы данных | Исправление причины и проверка реальной угрозы |

GSAP/Lenis, Three.js, шейдеры, частицы, кастомный курсор, тяжёлые переходы, автоматическое видео и новые библиотеки не входят в базовый стек. Их добавление требует конкретной пользы для выбранной концепции и проверки производительности. Figma используется, если понадобится редактируемый дизайн-файл; для согласования возможны обычные локальные браузерные прототипы. Генерация изображений не заменяет реальные работы и сотрудников.

## 9. Критерии приёмки

### Композиция и содержание

- Три разных направления представлены до полной реализации, каждое имеет мобильную версию.
- Выбранный стиль работает в услугах, карточках, меню и контактах, а не только на первом экране.
- Пользователь быстро находит стоимость, мастера и запись; знакомый клиент не проходит повторно длинную презентацию.
- Нет слоганов, декоративных надзаголовков, фиктивных отзывов, демонстрационных объяснений и случайных технологий ради эффекта.
- Существенные условия не прячутся ради краткости: ограничения услуги или акции доступны в нужный момент.

### Матрица экранов и действий

| Проверка | Обязательный результат |
| --- | --- |
| 320, 360, 390, 430 px | Нет горизонтальной прокрутки страницы и перекрытых действий; длинные кнопки перестраиваются |
| 768, 1024 px | Навигация и карточки переходят в подходящий режим без промежуточного развала |
| 1280, 1440, 1920 px | Контент сохраняет меру, изображения не теряют важное кадрирование |
| Низкий экран/горизонтальный телефон | До действий можно добраться, фиксированные панели не блокируют содержание |
| Увеличение 200% | Текст и управление доступны, кнопки не обрезаны |
| Кнопки на всех поддерживаемых размерах | Одна фактическая строка; ширина достаточна; поля от 12 px; нажатие от 44 px |
| Клавиатура | Все действия доступны, фокус видим и не теряется после закрытия слоя |
| Уменьшение анимации | Содержание и действия доступны без обязательного движения |
| Длинные/отсутствующие значения | Нет сломанных имён, пустых рамок, `undefined`, ложных обещаний и кнопок без назначения |

Браузеры: Chromium, Firefox и WebKit в доступной автоматизированной среде; отдельно реальный Safari/iOS и Android при наличии устройств. Эмуляция не выдаётся за физическую проверку. Блокер браузерного инструмента сначала решается доступным подходящим способом; непроведённая проверка остаётся явно непроведённой.

### Данные, код и производительность

- Нет ошибок сборки/типов и воспроизводимых ошибок консоли на основных сценариях.
- Необходимые проверки охватывают ссылки ресурсов, уникальность ID, связи, допустимые цены/длительности, формат контактов и проверенные параметры записи.
- Отдельный небольшой тест нужен для нетривиальной логики записи/преобразования данных. Декоративные CSS-значения не тестируются ради количества тестов.
- В итоговом HTML есть основное содержание. Для первого кадра заданы размеры, приоритет и разумный вес; нет обязательного автоматического видео.
- Цели Core Web Vitals: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1; полевой критерий относится к 75-му процентилю посещений. До публикации фиксируются лабораторные измерения и условия, без заявления о выполненных полевых показателях. Обычная загрузка Lighthouse не измеряет INP; для отклика нужны взаимодействия и последующие полевые данные. [Источник: Web Vitals](https://web.dev/articles/vitals).
- Бюджет собственных клиентских JS первой страницы: ориентир до 60 KB gzip без сторонних сервисов. Сторонние загрузки учитываются отдельно и не скрываются из оценки опыта пользователя.
- Чистая сборка не требует исходников брендбука и не содержит CDR/PSD/архивов, внутренних документов, локальных абсолютных путей или клиентских секретов.
- Сотрудник меняет цену/активность мастера/фотографию в одном понятном месте; инструкция соответствует проверенному процессу.

## 10. Порядок согласования

1. Сейчас владелец рассматривает состав разделов, работу с внешней библиотекой, предлагаемую архитектуру и последовательность. Одобрение плана запускает локальную работу по этапам.
2. После трёх прототипов владелец выбирает визуальное направление. Это необходимое решение для полного сайта; независимая подготовка данных может продолжаться.
3. После готового локального результата публикация получает отдельное поручение с конкретной площадкой. Одобрение дизайна не означает публикацию или создание реальных записей.

Остальные обычные обратимые решения и проверки выполняются самостоятельно в рамках согласованного объёма. Каждая завершённая задача сопровождается фактической проверкой, а не новым запросом разрешения.
