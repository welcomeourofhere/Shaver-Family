# Публичные фотографии работ СОЮЗа

Текущий режим workflow — `wall-works`. Он читает кандидатов с публичной стены сообщества `-210007626` единственным официальным методом `wall.get`, тем же методом, который уже работает в новостном потоке. Источник данных обозначается `vk-public-wall`: результат не называется выгрузкой альбомов.

## Граница чтения

`scripts/vk-public-work-photos.py` отправляет ключ только в POST к фиксированному `https://api.vk.com/method/wall.get`, с `v=5.199`, `owner_id=-210007626`, `filter=owner`, `count=100`. Максимум — шесть страниц и 600 полученных постов. Между запросами выдерживается минимум 0,36 секунды, повторы отсутствуют. Перенаправления запрещены, размер ответа одной страницы ограничен 4 MB. Нет cookies, браузерных сессий, внутренних API, OAuth, изменения разрешений или записей в аккаунт.

В кандидатах остаются только посты, у которых и `owner_id`, и `from_id` указывают сообщество, ID и дата — положительные целые, а текст содержит слова о волосах/стрижке/бороде/детских работах, имя одного из шести действующих мастеров или хештег «Товарищ». Это отбор для последующей проверки человеком, без автоматического назначения мастера, услуги, названия стрижки или категории. Чужие репосты и вложения других владельцев не добавляются.

Сохраняются все подходящие фото-вложения поста, а не только первое. Для каждого проверяются положительный photo ID, владелец сообщества, объявленные размеры и HTTPS URL официального CDN. Выбирается максимальный объявленный безопасный размер без изменения подписанного URL и без увеличения изображения. `albumId`, если он присутствует в attachment, сохраняется как исходное поле, включая системный ID стены; это не подтверждение чтения альбома.

Максимум — 120 уникальных постов-кандидатов. При достижении лимита чтение прекращается. JSON отдельно сообщает число страниц, полученных и фактически просмотренных постов, а также достижение лимита. Поэтому ограниченный каталог не объявляется полной историей всех работ.

## Результат и workflow

Workflow `soyuz-works.yml` запускается от push в `codex/soyuz-photos-read` и вручную. В актуальном workflow доступен только режим `wall-works`, с единственным `secrets.VK_TOKEN`, повторно использованным по прямому поручению владельца. Права GitHub — `contents: read`; новостной workflow не меняется.

На каждый кандидат выводится одна JSON-строка `SOYUZ_PUBLIC_WORK_POST=…`: исходный авторский текст, ID/ссылка поста, дата, photo ID, исходный album ID и размеры. Подписанные CDN URL остаются только в artifact JSON, чтобы лог был компактнее. После каталога выводится `SOYUZ_PUBLIC_WORK_RESULT=…` со статистикой.

Artifact `soyuz-vk-public-work-photos` хранит `vk-public-work-photos.json` семь дней. В нём есть исходные CDN URL, необходимые для последующего отбора и подготовки изображений. Ключ, `request_params`, исходный текст ошибки VK и прочие поля ответа не сохраняются. При отказе прежний успешный JSON остаётся, а отдельный `.error.json` содержит только категорию и числовой код. Если ответ неожиданно отражает значение ключа в разрешённом поле, запись результата и вывод каталога блокируются.

Из этого каталога основной агент проверяет реальную атрибуцию шести действующих мастеров и выбирает изображения. Только после курации создаются адаптивные варианты и подтверждённый manifest сайта. Reader не меняет `src`, Footer, галерею или статус опубликованных фотографий и сам ничего не публикует.
