# Чтение альбомов работ СОЮЗа

Изолированный серверный поток только для сообщества `-210007626`. Worker использует два официальных метода: `photos.getAlbums` для списка альбомов и `photos.get` для явно выбранных ID. Записи, сообщения, редактирование стены и административные действия отсутствуют. Браузерная страница альбомов не используется.

## Фактически проверенная граница доступа

16 ноября 2026 основной агент запустил workflow: [run 43862353020](https://github.com/welcomeourofhere/Shaver-Family/actions/runs/43862353020), job `133282119889`. Модульные тесты прошли; серверное чтение `photos.getAlbums` завершилось безопасным ответом `api_error`, код `1051`. Ключ и исходные параметры запроса не читались из логов и не записывались в результат. Успех действующего ключа для новостей стены не подтверждает доступ к альбомам.

Значение `1051` не истолковывается как доказательство конкретной причины или недостающего разрешения. Проверенная официальная [схема методов VK](https://github.com/VKCOM/vk-api-schema/blob/master/photos/methods.json) указывает типы токенов `user` и `service` для обоих методов; работоспособность community-key из управления сообществом не установлена. Другие ключи, методы и разрешения после отказа не перебираются.

Владелец выбрал отдельный доступ и сам вводит его в GitHub Actions Secret `SOYUZ_VK_PHOTOS_TOKEN`. Шаг чтения альбомов передаёт только этот secret в переменную процесса `SOYUZ_VK_TOKEN`. Этот шаг и worker альбомов не используют резервные `SOYUZ_VK_TOKEN`/`VK_TOKEN` из новостного потока или Shaver Family. При отсутствии нового secret поток завершается `missing_token` до сетевого обращения. Запрашивается только возможность чтения фотографий; права сообщений, изменения стены и администрирования этому потоку не нужны. Успешный доступ считается подтверждённым только после нового серверного результата.

## Поиск существующего приложения

По следующему прямому поручению владельца используется уже существующее приложение Shaver Family. Для получения его публичных метаданных добавлен отдельный `scripts/vk-app-metadata.py`: единственный метод `apps.get`, только POST с `v=5.199`, без `app_id` и `app_ids`, без перенаправлений и повторов, с лимитом ответа 512 KiB. Из ответа принимается ровно одно приложение и только поля `id`, `title`, `type`. URL, ключ, параметры запроса и исходный текст ошибки в вывод не попадают. Успех выводится строкой `SOYUZ_VK_APP_METADATA=…`, отказ — только категорией и числовым кодом.

В [официальной схеме apps.get](https://github.com/VKCOM/vk-api-schema/blob/master/apps/methods.json) `app_id` и `app_ids` необязательны, типы токенов — `user`/`service`. Схема прямо не объясняет результат при отсутствии ID, поэтому принадлежность возвращённого приложения подтверждается фактическим серверным ответом, а не предположением. При пустом или неоднозначном списке ID не выбирается.

Текущий режим push в `codex/soyuz-photos-read` — `app-metadata`. Он использует исключительно существующий `secrets.VK_TOKEN` в отдельном шаге. В этом режиме шаг `photos.getAlbums`/`photos.get` и выгрузка фото не выполняются. Настроенный `SOYUZ_VK_PHOTOS_TOKEN` сохранён. Это отдельное разрешённое чтение публичных метаданных, а не резервный ключ для альбомов. OAuth, выдача прав, изменение разрешений и любые записи отсутствуют; новостной workflow не меняется.

## Два этапа чтения

1. Пустой `SOYUZ_WORK_ALBUM_IDS` — только список альбомов. Строка `SOYUZ_ALBUM_CATALOG=…` в job log содержит ID, название, количество фото и первые 400 символов описания. Она не содержит фото, размеров и CDN URL. Полное описание остаётся в artifact JSON.
2. После проверки названий альбомов явно задаются нужные ID через `SOYUZ_WORK_ALBUM_IDS` в workflow или dispatch input `album_ids`. Только для этих альбомов вызывается `photos.get`. В JSON сохраняются исходные подписи, owner/album/photo ID, даты и максимальный объявленный безопасный размер изображения. Полные фамилии, `masterId`, названия стрижек и связь с услугой автоматически не назначаются.

Для описанных двух этапов альбомов требуется явно выбрать режим `albums` в `workflow_dispatch` либо изменить согласованный режим workflow отдельным коммитом. Права GitHub — `contents: read`; результат альбомов сохраняется как Actions artifact `soyuz-vk-work-albums` на семь дней. Автоматической публикации, коммита или загрузки изображений в сайт нет. При API-ошибке прежний успешный JSON сохраняется, а отдельный `.error.json` содержит только категорию и числовой код. В worker альбомов код 6 имеет ограниченный повтор; 1051, 5 и 27 повторов и расширения доступа не вызывают. Metadata-reader не повторяет ни один отказ.

После успешного чтения отдельно сверяются шесть действующих мастеров, авторство и подписи, затем подготавливаются оригиналы/адаптивные варианты и их происхождение для сайта. До этого опубликованные данные о работах не получают отметку подтверждения из альбомов.

Локальная проверка без ключей и сети:

```powershell
python -m unittest discover -s tests -p 'vk_work_albums_test.py'
python -m unittest discover -s tests -p 'vk_app_metadata_test.py'
python -m py_compile scripts/vk-work-albums.py tests/vk_work_albums_test.py
python -m py_compile scripts/vk-app-metadata.py tests/vk_app_metadata_test.py
```
