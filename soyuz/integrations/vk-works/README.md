# Чтение альбомов работ СОЮЗа

Изолированный серверный поток только для сообщества `-210007626`. Worker использует два официальных метода: `photos.getAlbums` для списка альбомов и `photos.get` для явно выбранных ID. Записи, сообщения, редактирование стены и административные действия отсутствуют. Браузерная страница альбомов не используется.

## Фактически проверенная граница доступа

16 ноября 2026 основной агент запустил workflow: [run 43862353020](https://github.com/welcomeourofhere/Shaver-Family/actions/runs/43862353020), job `133282119889`. Модульные тесты прошли; серверное чтение `photos.getAlbums` завершилось безопасным ответом `api_error`, код `1051`. Ключ и исходные параметры запроса не читались из логов и не записывались в результат. Успех действующего ключа для новостей стены не подтверждает доступ к альбомам.

Значение `1051` не истолковывается как доказательство конкретной причины или недостающего разрешения. Проверенная официальная [схема методов VK](https://github.com/VKCOM/vk-api-schema/blob/master/photos/methods.json) указывает типы токенов `user` и `service` для обоих методов; работоспособность community-key из управления сообществом не установлена. Другие ключи, методы и разрешения после отказа не перебираются.

Владелец выбрал отдельный доступ и сам вводит его в GitHub Actions Secret `SOYUZ_VK_PHOTOS_TOKEN`. Workflow передаёт только этот secret в переменную процесса `SOYUZ_VK_TOKEN`. Ни workflow, ни worker не используют резервные `SOYUZ_VK_TOKEN`/`VK_TOKEN` из новостного потока или Shaver Family. При отсутствии нового secret поток завершается `missing_token` до сетевого обращения. Запрашивается только возможность чтения фотографий; права сообщений, изменения стены и администрирования этому потоку не нужны. Успешный доступ считается подтверждённым только после нового серверного результата.

## Два этапа чтения

1. Пустой `SOYUZ_WORK_ALBUM_IDS` — только список альбомов. Строка `SOYUZ_ALBUM_CATALOG=…` в job log содержит ID, название, количество фото и первые 400 символов описания. Она не содержит фото, размеров и CDN URL. Полное описание остаётся в artifact JSON.
2. После проверки названий альбомов явно задаются нужные ID через `SOYUZ_WORK_ALBUM_IDS` в workflow или dispatch input `album_ids`. Только для этих альбомов вызывается `photos.get`. В JSON сохраняются исходные подписи, owner/album/photo ID, даты и максимальный объявленный безопасный размер изображения. Полные фамилии, `masterId`, названия стрижек и связь с услугой автоматически не назначаются.

Workflow запускается от push в `codex/soyuz-photos-read` и вручную через `workflow_dispatch`. Права GitHub — `contents: read`; результат сохраняется как Actions artifact `soyuz-vk-work-albums` на семь дней. Автоматической публикации, коммита или загрузки изображений в сайт нет. При API-ошибке прежний успешный JSON сохраняется, а отдельный `.error.json` содержит только категорию и числовой код. Код 6 имеет ограниченный повтор; 1051, 5 и 27 повторов и расширения доступа не вызывают.

После успешного чтения отдельно сверяются шесть действующих мастеров, авторство и подписи, затем подготавливаются оригиналы/адаптивные варианты и их происхождение для сайта. До этого опубликованные данные о работах не получают отметку подтверждения из альбомов.

Локальная проверка без ключей и сети:

```powershell
python -m unittest discover -s tests -p 'vk_work_albums_test.py'
python -m py_compile scripts/vk-work-albums.py tests/vk_work_albums_test.py
```
